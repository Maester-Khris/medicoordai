### Performance notes for Stage C (from the high-perf-browser and Postgres skills)
- **Frontend.** Sort once with `useMemo` keyed on the facility list and a rounded origin (a new coords object each render must not re-sort). Render 8 rows, grow by 8 with one `IntersectionObserver` sentinel, no scroll listener. Fixed 56 px rows with `content-visibility: auto` so loaded rows cost no layout until visible, and no layout shift. Mount the list only while the sheet is in `half`. Memoised row component; no work inside the tap handler beyond a state set (INP).
- **Map re-render (found while reading `FacilityMarkerLayer`).** `getFacilityIcon` builds a new `divIcon` for every facility on every `MapPanel` render, and `MobileLayout` re-renders on every keystroke (`omniValue`) and sheet change, so about 300 icons are rebuilt per keystroke. Fix (task C4): `React.memo(MapPanel)` with stable callbacks in `MobileLayout`. "Show on map" uses a single `flyTo` plus one highlight circle, not an icon change on all markers. Not measured yet; C4 measures render counts before and after.
- **Backend (no change in this task).** `/facilities` already sends `ETag` and `Cache-Control: max-age` and the client sends `If-None-Match`. No `GZipMiddleware` was found in `backend/main.py`, so about 121 KB of JSON for 308 facilities may travel uncompressed unless the Railway edge compresses it (unverified). Listed as a follow-up for a backend task. The Postgres skill has nothing to apply here: no query or schema changes, and the list sorts client-side.
